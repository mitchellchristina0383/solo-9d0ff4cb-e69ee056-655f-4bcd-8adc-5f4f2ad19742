# VPN 换线 · MTU 黑洞演练台（Flask + Docker Compose）

一个单页交互式演练工具，用来复现这个典型故障：

> VPN 换线后小包能通、大报表卡住。报文置 DF（禁止分片），一旦
> `载荷 + 封装开销 > 线路 MTU` 就在线路侧被丢弃；超长通知（ICMP too-big）
> 可能被过滤形成静默黑洞，只能等超时缩包。换线后载荷重新从起始值试发，
> 旧线在途报文的回执仍会到达，与新线回执乱序交错、区间重叠。

## 启动

### Docker Compose（推荐）

```bash
docker compose up --build
# 打开 http://localhost:8000
```

镜像用 `python:3.12-slim`，入口为 `gunicorn -w 1 --threads 8`
（内存态演练，必须单 worker；多线程足够单人/小班使用）。
`compose.yaml` 带 `/healthz` 健康检查。

### 本地直接运行

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
python app.py            # http://127.0.0.1:8000
```

跑测试：

```bash
pip install pytest
pytest                   # 10 个 API/引擎用例
```

## 页面能做什么

1. 填写 **报表字节数**、**起始载荷**、**超时缩包步长**；
2. 分别设置 **线路 A / B 的 MTU、封装开销、超长通知开关**，
   参数卡实时显示 `MTU - 封装开销` 的最大载荷以及起始包是否必超；
3. **发下一包** / 填数量 **连续发包** / **连续发完剩余新包**；
4. 每个在途包可单独点 **回执 ACK** 或 **触发超时**；
   也可选择正序 / 逆序 / 随机乱序，**依次批量回执**，或只随机回一个；
5. 超长通知打开时，超大包被丢弃并产生“待投递通知”，由你手动点
   **投递超长通知**（可以先换线再投递，观察“过期轮次通知不缩包”）；
6. **换到线路 A/B 并立即重发**：载荷重置为起始载荷、轮次 +1，
   并按新载荷把所有未确认字节重新打包立即发出；
7. 表格显示每包的 **线路、轮次、类型、载荷长度、封装后长度、
   字节区间 `[起,止)`、协议状态与上帝视角的物理结果、操作按钮**；
8. 顶部实时显示 **累计确认字节数 / 总字节数 / 百分比**、合并后的确认区间、
   区间 chip 和覆盖图（绿色为确认区间，彩色描边为各包范围）；
9. `累计确认 == 报表字节数` 时显示“全部传完”横幅，并发新包/换线会被拒绝，
   重复/重叠回执保持幂等；
10. **多标签页代次隔离**：每次重置都分配新的“代次令牌”（generation，状态条
    可见）。一个标签页重置演练并重发同号包后，另一个标签页迟到的旧回执等
    写请求会被服务端以 409 退回，绝不可能误确认新演练里编号相同的包；
    批量回执途中发现代次已换会立即停止；前端迟到的旧响应也不会把画面切回
    旧演练。同一场演练内换线**不**换代次，旧线回执照常确认对应字节。

## 核心规则与实现对应

代码分两层：

- `drill_engine.py`：纯逻辑。`Drill`（演练状态）、`Packet`、
  `DrillConfig/LineConfig`、`AckedRanges`（合并区间并集与未确认打包）。
- `app.py`：Flask 路由 + 全局 `Drill` 单例 + `RLock`，所有响应回传完整 state。
- `templates/index.html`、`static/app.js`、`static/style.css`：原生 JS 单页，
  无外部 CDN/依赖，每 2.5s 轮询一次，所有写操作后立即用响应 state 重渲染。
- **代次令牌（generation）**：`Drill` 持有一个字符串令牌，`/api/reset` 每次
  生成新令牌（`gen-1`、`gen-2`……）并放进 state。除 reset 外的所有写接口
  先校验请求体里的 `generation` 是否等于当前令牌，不一致直接返回 409 且
  不改任何状态；缺少该字段的请求视为旧客户端、兼容放行。前端 `app.js`
  从 state 记住令牌，写请求自动携带；收到 409 或在轮询中发现新令牌就把
  画面整体切到新演练，旧响应受请求序号（`refreshSeq`）保护，无法回切。

关键语义：

- **字节编号**：从 0 开始，区间左闭右开，`[0,1400)` 即前 1400 字节。
- **DF 判定**：发包时计算 `wire = size + overhead`，`wire > mtu` 即物理丢弃：
  - 通知关 → `silent_drop`：发送端仍显示“在途”，且不允许 ACK（上帝视角标明
    实际已静默丢弃），只能由演练者点“触发超时”；
  - 通知开 → `notify_drop`：生成 pending 的超长通知，可手动投递。
- **轮次（round）**：每包盖当前轮次号。一次有效的通知缩包或超时缩包会让
  轮次 +1。旧轮次包的通知/超时只记录事件、**不再缩包**。超时若来自当前轮，
  载荷减一个步长（下限 1），并立即用新载荷重发最早的未确认连续段；
  超长通知则把载荷降到 `MTU - overhead`。
- **换线**：`active_line` 切换、`cur_payload = start_payload`、轮次 +1，
  然后调用 `resend_missing(kind="switch")` 立即重发全部未确认字节。
- **回执与去重**：ACK 把包区间加入 `AckedRanges` 的合并区间并集，
  返回本次“新增字节数”；重叠/重复区间新增 0，累计确认只按并集长度计算一次。
  超时后的在途包仍可“补到迟到回执”，并打 `late_ack` 标记。
- **重发只取未确认字节**：`AckedRanges.packetize_unacked(max_len)`
  跳过所有已确认区间，把未确认字节按当前载荷切成连续段；遇到已确认区间
  立即断段，所以重发包可能短于设定载荷。
- **规模保护**：报表 ≤ 1,000,000 字节，最多 5,000 个包；“连发全部”前先估算包数，
  超限直接 400 且不改状态。

## API 一览

| 方法/路径 | 作用 |
| --- | --- |
| `GET /api/state` | 完整演练状态 |
| `POST /api/reset` | 用 JSON 参数重置（空体=默认参数） |
| `POST /api/send-next` | 发下一包（优先推进新字节，否则补最早缺口） |
| `POST /api/send-burst` | `{"count": 8}` 连发；`{"count":"all"}` 发完剩余新字节 |
| `POST /api/resend-missing` | 按当前载荷重发全部未确认字节 |
| `POST /api/switch` | `{"line":"B"}` 换线、重置载荷并立即重发 |
| `POST /api/packets/<id>/ack` | 回执（支持超时后的迟到回执，重叠自动去重） |
| `POST /api/packets/<id>/timeout` | 触发超时（仅当前轮缩包并重发） |
| `POST /api/packets/<id>/deliver-notice` | 投递超长通知（旧轮通知被忽略） |
| `GET /healthz` | 健康检查 |

错误统一为 `{"ok": false, "error": "..."}`，400 参数/规模问题、404 包不存在、
409 当前状态不允许（如 ACK 一个实际已丢弃的包、传完后再发），或请求携带的
`generation` 与当前演练不一致（演练已被重置的迟到写请求）。

> 除 `POST /api/reset` 外，所有写接口都接受可选的 `generation` 字段：
> 前端会自动带上当前 state 里的令牌；令牌过期返回 409。不带字段的旧客户端
> 不受影响（兼容放行）。`/api/state` 的 state 与各写响应里都含 `generation`。

## 推荐手动演练脚本

**A. 静默丢包（默认参数即是此场景）**

1. 默认 `报表 10000 / 起始载荷 1400`，A 线 `1500 / 120 / 通知关`
   （最大载荷 1380），B 线 `1500 / 60 / 通知开`（最大载荷 1440）；
2. 连发包数填 8，点“连续发包”：前面的满包显示红色“静默丢弃”，
   最后一个短包可能实际在途——这就是“小包能通、大包卡住”；
3. 尝试给红色静默丢包点 ACK 会被拒绝；对它点“触发超时”：
   载荷 `1400 → 1200`、轮次 +1，并自动重发 `[0,1200)`；
4. 对在途包任意顺序 ACK，再点“重发全部未确认”，直到绿色“全部传完”。

**B. 换线后的回包交错与重叠去重**

1. 可用测试里的参数：报表 `4200`，A 线开销 `200`（最大载荷 1300，通知关）；
2. 连发 3 包 → 对 `#1` 超时缩到 1200 → ACK 重发包 `#4` → “重发全部未确认”；
3. 在任何回执前点“换到线路 B 并立即重发”：载荷回到 1400，
   新包区间从尚未确认的 1200 开始，与 A 线在途包大面积重叠；
4. 用每包按钮按 `B#9 → 旧A#5 → B#8 → 旧A#6 → B#10` 的顺序回执，
   可看到累计确认 `2600 → 3800 → 4000（重叠只 +200）→ 4000（完全覆盖 +0）
   → 4200 传完`；给旧 A 线包补超时会提示“旧轮次不缩包”，但之后仍可迟到 ACK。

**C. 超长通知轮次**：点“预设：A 有超长通知”，连发 3 个满包后，
先投递任意一个通知：载荷一次性降到 1380；再投递同批其它通知，
会显示“过期轮次通知·已忽略”，不会重复缩包。

**D. 两个标签页交错：重置隔离（本项目新增的核心场景）**

1. 开两个浏览器标签页都打开 `http://localhost:8000`，确认状态条的
   “演练代次”相同（如 `gen-1`）；
2. 标签页 T1 连发 3 包，先**不要**回执；
3. 切到标签页 T2，点“应用参数并重置演练”，再连发 3 包 —— 状态条代次
   变为 `gen-2`，新演练里又出现了编号 `#1..#3` 的包；
4. 回到 T1（画面仍是旧演练），点旧 `#3` 的“回执 ACK”：收到 409 提示
   “演练已被重置……”，T1 随即自动刷新为新演练（代次 `gen-2`），新演练
   的 `#3` 保持“在途未回执”，确认字节没有被旧回执污染；
5. 或在 T1 点“依次回执所有在途可收包”后立刻去 T2 重置：T1 的批量回执
   在第一个 409 处即停止，辅助区显示“演练已重置，批量回执已停止”，
   新演练报文一个都不会被确认；
6. 对照：不重置、只在 T1 点“换到线路 B 并立即重发”（同一场演练，代次
   不变），旧 A 线报文的 ACK 仍然正常确认对应字节，重叠部分只去重。

## 限制与余项

- **单演练实例、内存态**：全局一把锁，刷新页面状态还在（同一服务进程），
  但重启即丢；不支持多房间/多学员隔离，如需多人同时使用要加 session/房间维度。
- 这是**协议行为仿真**，不发真实 ICMP、不操作真实网卡/路由；
  “上帝视角”的物理丢弃标记是教学设计，不是抓包结果。
- 超时由演练者手动触发（不做真实倒计时），便于确定性地演示乱序/交错；
  页面有 2.5s 轮询但没有自动发包/自动超时。
- 本沙箱无 Docker，**`docker compose up --build` 未在本机实跑**；
  本次仅做了 `compose.yaml` YAML/字段校验与 Dockerfile 同款 gunicorn
  启动验证，首次在有 Docker 的机器构建时需确认网络可拉取
  `python:3.12-slim` 与 pip 依赖。
- 代次令牌是**服务端进程内的单调计数器**，gunicorn 固定单 worker
  （内存态演练的既有约束）；若将来扩成多 worker/多实例，需要把令牌与
  演练状态一起搬到共享存储。不带 `generation` 的请求按旧客户端兼容放行，
  因此隔离能力依赖前端升级；浏览器直连 API 且故意不带令牌的调用无法被
  代次机制拦截（教学工具、可信网络内使用）。
- 未做鉴权与审计，仅限本地/可信教学网络；不要直接暴露到公网。
